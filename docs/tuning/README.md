# Greplet 튜닝 이력 — 누적 기록

> 공개용 익명 표기: 테스트 대상 함수·클래스·프로젝트·질문 ID와 로컬 경로를 대체했다. `Type001.Method001`은 함수 F001을 뜻하며 실제 식별자가 아니다. 평가 수치와 순위는 원본 그대로다. 원본 질문·결과·대응표는 로컬에만 보관하며, 예시 경로는 실제 위치가 아니다.

**목적:** 어떤 문제를 해결하려고 무엇을 바꿨고, 동일 조건의 전후 결과를 보고 왜 채택·보류했는지 남긴다. 이후 실험은 아래에 새 ID로 추가하며, 과거 결과는 덮어쓰지 않는다.

**최근 결과 바로 보기:** [T12 워크스페이스 선택기 전후 비교](2026-09-11-workspace-routing.md) · [T11 실사용 로그·동시 요청 검증](2026-09-11-release-validation.md) · [T10 융합 순위 튜닝 전후 비교](2026-09-11-vector-prefix.md). T07~T09 평가와 실행 도구는 `6aa26ed`에 기록했다.

**T12 후속 연구 검토:** [ReSLLM·MKP-QA·RAGRoute 비교](2026-09-11-workspace-routing-research.md) — 연구별 결과·학습 조건·한계, T12와의 차이, 다음 검증 우선순위. 추가 검색 실험 없이 정리한 참고 자료다.

**현재 운영 구성:** 요청 내 임베딩 공유 + `keep_alive=30m` + 정확한 `Type.Member` 정의 우선 검색. **단일 워크스페이스는 벡터 상위 3개 보호 후 4:1 가중 RRF 순서로 채우며, 여러 워크스페이스는 기존 4:1 가중 RRF를 유지**한다. bge-m3·BM25·운영 청크는 기존 설정 유지. T10 구현은 `ce20623`으로 커밋했으며 운영 반영 후 검증했다.

## 비교 기준과 적용 검증

**최신 결과:** T12의 자동 선택기는 채택 기준을 충족하지 못했다. 정답 범위를 직접 주면 hybrid 적중이 17→34/80으로 늘지만 자동 선택은 이를 재현하지 못했고, 정답 범위 vector도39/80에 머물렀다. 범위 선택과 후보·최종 순위 개선을 각각 검증한다. T12는 신규 작성 질문이며 과거 실사용·단일 범위 결과와 분모가 다르다. 전체 에이전트 행동·안전성 평가는 미관측이다.



- **기준 관계:** T01·T02는 같은 성능 개선 커밋에 포함됐다. T01은 예열된 검색 비교, T02는 별도 서버 유휴 비교로 검증했다. T03·T04·T05는 **T01+T02가 적용된 공통 기준선**에서 갈라진 실험이다. T03→T04→T05 순서로 운영에 누적 적용한 것이 아니다.
- **품질 조건:** T03~T05는 같은 코드·문서 혼합 40문항, 3모드, 5회, 캐시 우회로 기준선 포함 **2,400회** 비교. 적중@5는 지정 함수/페이지가 상위 5개에 있는지다. 반복 실행은 독립 정답 표본으로 세지 않는다.
- **범위:** 지연은 로컬 측정이며 HTTP·동시 부하를 제외했다. T02 유휴 비교는 1회로, 최초 로딩이나 30분 초과 유휴까지 없애지는 않는다. 유지 비용은 관측상 모델 VRAM 약 664MB다. 문맥 실험 DB는 새로 구축했으므로 그 지연을 운영 DB와 성능 비교하지 않는다.
- **최종 검증:** 빌드·관련 회귀 테스트 통과. T04 운영 API **120건**의 ID·순서·점수 일치. 운영 10개 워크스페이스 유지, 재색인 없이 반영.

## 다음에 쌓을 실험

[T12 사전 계획](2026-09-11-workspace-routing-plan.md)은 [구현·학습·신규100개 시험까지 완료](2026-09-11-workspace-routing.md)했다. 운영 auto 연결은 품질 기준 미달로 진행하지 않았다. [후속 연구 검토](2026-09-11-workspace-routing-research.md)를 바탕으로 유사한 범위 사이의 확정 음성 라벨, LLM 선택기 기준선, 범위 선택과 최종 점수 결합의 효과를 각각 검증하는 것을 제안한다. 아직 추가 실험은 실행하지 않았으며, T12의 100개는 이후 미사용 시험군으로 재사용하지 않는다.

[2차 튜닝 전 기준선](2026-09-11-round2-baseline.md): 당시 구현으로 동일 40문항 × 3모드 × 5회, **600회 재측정 완료**. 이전 측정과 결과 ID·순서·점수가 모두 같았다. 이후 T06에서 튜닝 후 비교까지 완료했다.

[자연어 후속 분석·실사용 기록](natural-language-followup.md): 기존 자연어 21개 중 vector만 적중한 4개와 두 모드 모두 놓친 8개를 분리했다. 새 튜닝 결과가 아닌 기존 데이터 재분류이며, 새 실패 사례 기록 양식을 함께 둔다.

**미해결:** 원래 함수 F001의 자연어 질문은 현재 hybrid에서도 목표 함수를 놓친다. BM25는 이미 구현돼 있으며, 이번 결과는 임베더 재학습 필요성을 입증하지 않았다.

**후속 과제:** T10에서 후보 풀을 고정한 융합 비교까지 완료했다. 남은 벡터 단독 적중 3개와 워크스페이스 간 순위 결합을 다음 가설로 남긴다. **예비 15문항은 T10에서 처음 평가했으므로 이제 미사용 보류군이 아니다.** 이후 튜닝의 독립 확인에는 새 보류군을 준비한다. 과거 실험 수치는 각 시점의 기록으로 유지한다.

**추가할 때 기록할 항목:** `ID·날짜 → 기준 커밋/설정 → 문제·가설 → 변경한 코드/파라미터 → 고정 평가 조건 → 전후 수치·회귀 → 채택/보류 → 구현 커밋·원시 결과 링크`. 효과를 확인하지 않은 변경은 결과 대신 **미검증**으로 남긴다.

공개용 집계 데이터: [2026-09-11.json](results/2026-09-11.json). 원본 식별자·질문 본문·소스·절대경로를 포함하지 않는다.

**공개 자료 검증:** 저장소 루트에서 `node scripts/report-retrieval-results.mjs --check`로 전체 결과 부록이 공개 JSON과 일치하는지 검사한다. `node scripts/test-retrieval-trace.mjs`는 분류 규칙과 관측 코드의 요청 분리·원본 반환을 검사하며 `indexer` 의존성 설치가 필요하다. 두 검사는 CI에서도 실행한다. 실제 검색 재실행에는 별도로 보관한 비공개 평가 자료가 필요하다.
