# Greplet 튜닝 히스토리

**무엇을 왜 바꿨고, 같은 조건에서 결과가 어떻게 달라져서 채택하거나 보류했는지 기록합니다.** 실험 ID와 당시 결과를 유지하며, 후속 결과는 새 기록으로 추가합니다.

**최근 판단:** [T12 자동 워크스페이스 선택기](2026-09-11-workspace-routing.md)는 채택 보류입니다. [T11 실사용·동시 요청 검증](2026-09-11-release-validation.md)까지 확인한 운영 구성을 유지합니다. 후속 방향은 [ReSLLM·MKP-QA·RAGRoute 연구 비교](2026-09-11-workspace-routing-research.md)에 정리했습니다.

## 현재 운영 구성

| 영역 | 적용한 동작 | 근거 |
|---|---|---|
| 임베딩 비용·유휴 지연 | 요청 안에서 질의 임베딩 공유, 모델 유지 시간 `30m` | T01·T02 |
| 정확한 정의 조회 | hybrid의 `Type.Member` 입력은 임베딩 없이 정의 우선 조회 | T04 |
| 단일 워크스페이스 융합 | 벡터 상위 3개 우선 배치 후 벡터:FTS 4:1 가중 RRF(k=60)로 나머지 구성 | T06·T10 |
| 복수 워크스페이스 융합 | 벡터:FTS 4:1 가중 RRF(k=60) | T06·T10 |
| 검색 범위 | 사용자가 지정하거나 전체 검색. 자동 선택기는 운영 API에 미연결 | T12 |

현재 기록의 운영 버전은 **0.11.2**입니다. bge-m3 재학습이나 운영 청크 변경은 채택하지 않았습니다. BM25는 이미 구현된 검색 구성 요소이며 이번 실험에서 새로 작성한 기능이 아닙니다.

## 튜닝 히스토리

아래 T01~T12는 모두 **2026-09-11** 기록입니다. 각 행의 전후 값은 해당 평가 조건 안에서 비교한 값입니다. 다른 행의 수치를 이어 붙여 누적 성능으로 계산하지 않습니다.

### 1. 지연·정의 조회·문맥 보강

|---|---|---|---|

| **T02** | 유휴 후 재로딩 → `keep_alive` 기본 5m 대신 명시적 30m | 약 327초 유휴 후 **2,470.5→27.7ms**. 그중 로딩 **2,419.3→1.5ms**, 벡터 동일 | **채택** · `4f72360` · [유휴 검증](2026-09-11-idle-validation.md) |

### 3. 실사용 확인과 워크스페이스 선택

| ID | 문제 → 변경한 방법 | 동일 조건 전 → 후 | 결정·근거 |
|---|---|---|---|
| **T11** | 릴리스 전 실제 질문·동시 요청 확인 → T10 정책 고정, 로그 **24문항 전부 실행·22개 채점**, 동시 요청 1·4·8개 | 지정 범위 **16→18/22**, 적중 손실 0. 전체 **4→4/22**. 8개 동시 요청 p95 **480.5→483.3ms**, 오류·혼선 0 | **0.11.2 릴리스 전 검증 통과** · [품질·부하·한계](2026-09-11-release-validation.md) |
| **T12** | 전체 검색의 방해 후보 축소 → 설명 임베딩 A1 vs 고정 임베딩 위 ML A2. 개발 200개로 설정 후 **새 100 × 4방법 × 2정책 × 3회**, 별도 진단 포함 **3,532회** | 채점 80개: 전체 **17**, A1 **17**, A2 **16**. T12 A1의 MRR은 **0.1660→0.1567**로 하락했습니다. 해당 요청은 범위를 줄이지 않고 전체 검색으로 보류했으며, 동점 후보의 **목록 정렬 효과**로 하락이 재현됐습니다. 범위 선택 자체의 품질 하락으로 단정하지 않습니다. A2는 클래스당 확정 음성이 범위 밖 질문 5개뿐이어서 유사 범위끼리 구분할 학습 근거가 부족했습니다. LLM 선택기는 미실행입니다.

## 비교 기준과 적용 검증

| 읽을 때 구분할 것 | 기준 |
|---|---|
| **적중과 순위** | 적중@5는 지정 근거 중 하나 이상이 상위 5개에 있는지, MRR@5는 첫 정답의 순위를 봅니다. 적중 유지와 순위 유지가 같지는 않습니다. T12의 복수 근거 완성은 모든 필수 근거가 상위 5개에 있어야 합니다. |
| **질문 수와 실행 횟수** | 반복 실행은 안정성 검사이며 독립 질문을 늘리지 않습니다. T03~T05는 같은 혼합 40문항을 기준선 포함 2,400회 비교했고, T11은 24개 실행 중 22개 채점, T12는 100개 실행 중 답이 있는 80개 채점입니다. |
| **이미 사용한 평가군** | T07의 100개는 T09에서 재실행하고 T10에서 개발군으로 사용했습니다. 별도 예비 15개는 T07·T09에서 미실행이었고 T10 후보 동결 후 처음 평가했습니다. 이 15개와 T12의 신규 100개도 이후 미사용 시험군으로 다시 세지 않습니다. |
| **정답 범위 진단 AO** | T12 운영 융합 정책에서는 전체 **17→AO 34/80**, 모든 범위에 4:1 RRF를 고정하면 **17→33/80**입니다. vector는 전체 **24→AO 39/80**입니다. AO는 정답을 사용한 진단이며 배포 가능한 선택기나 보장된 상한이 아닙니다. |
| **지연 측정 범위** | 초기 T01~T05 지연은 로컬 비교이며 HTTP·동시 부하를 제외했습니다. T02는 유휴 비교 1회이고 모델 VRAM은 관측상 약 664MB였습니다. T06의 약 +3ms도 별도 시간대 측정이므로 전부 재정렬 비용으로 해석하지 않습니다. T11의 동시 요청 검사와 T12의 고정 엔진 내부 측정은 각 보고서 조건으로 읽습니다. 문맥 실험의 새 DB 지연을 운영 DB와 비교하지 않습니다. |
| **실패 단계와 전체 성공** | T12 최종 top5 탈락에는 단일 범위 안에서 6위 이하인 경우도 포함됩니다. 모두 범위 간 경쟁 탓으로 돌리지 않습니다. AgentAudit 참고 평가는 검색 단계 진단이며 전체 에이전트 행동·안전성·최종 답변 정확성은 미관측입니다. |

운영 적용 시점의 검증도 각 보고서에 남겼습니다. 예를 들어 T04는 대상 외 **560회 결과 동일**, 운영 API **120건의 ID·순위·점수 일치**를 확인했습니다. 이후 T10·T11의 범위·동시 요청 검증과 T12의 오프라인 검증을 별도 기록으로 관리합니다.

## 다음에 쌓을 실험

**아직 추가 검색 실험은 실행하지 않았습니다.** [T12 사전 계획](2026-09-11-workspace-routing-plan.md)의 오프라인 구현·학습·신규 100개 시험은 완료했으나, 운영 auto 연결과 실사용 관찰은 채택 기준 미달로 진행하지 않았습니다.

| 우선순위 | 검증할 가설·작업 | 판단할 근거 |
|---|---|---|
| 1. 설계·라벨 | [연구 비교](2026-09-11-workspace-routing-research.md)를 먼저 검토하고, 유사 범위 간 확정 음성·복수 정답 라벨 보강 | 미판정을 음성으로 바꾸지 않고, 범위를 구별할 근거가 충분한지 확인 |
| 2. 선택·순위 분리 | 설명 유사도·학습형·LLM 기준선 비교. 범위 선택과 최종 점수 결합의 효과를 각각 측정 | 필수 범위 보존, 적중·MRR·복수 근거 완성, 실제 검색 범위 수·지연 |
| 3. 독립 확인 | 작은 개발 실험 후 설정 동결, 새 시험군으로 확인 | 기존 결과를 본 질문에 맞춘 개선과 새 질문에서의 개선을 구분 |

T10 당시 남은 벡터 단독 적중 3개와 워크스페이스 간 순위 결합도 후속 가설입니다. 기존 함수 F001의 자연어 질문은 해당 평가에서 hybrid로 찾지 못했습니다. 이 기록만으로 임베더 재학습이 필요하다고 결론 내리지 않습니다.

## 기록·공개 원칙

- **과거 결과 보존:** 후속 결과가 달라도 당시 수치를 덮어쓰지 않습니다. 새 구현·평가·연구 검토를 구분해 기록하고, 효과를 측정하지 않은 변경은 **미검증**으로 표시합니다.
- **익명 공개:** 테스트 대상 함수·클래스·프로젝트·질문·로컬 경로를 익명화하고 수치·순위는 유지합니다. `Type001.Method001`은 F001의 공개 별칭입니다. 원문·소스·대응표·절대경로는 공개하지 않습니다. T01~T05의 실명 원본을 포함한 미공개 커밋은 로컬 백업 후 익명화된 변경으로 정리했습니다.
- **실험을 추가할 때:** 아래 항목을 새 보고서에 남기고 해당 행을 이력에 추가합니다. 개선 합계와 함께 적중 손실·순위 하락·실패 단계도 기록합니다.

```text
ID·날짜 → 기준 커밋·설정 → 문제·가설 → 변경 코드·파라미터
→ 고정 평가군·분모·반복 → 전후 수치·회귀 → 채택·보류
→ 구현 커밋·공개 집계·근거 보고서
```
