> 공개용 익명 표기: 테스트 대상 함수·클래스·프로젝트·질문 ID와 로컬 경로를 대체했다. `Type001.Method001`은 함수 F001을 뜻하며 실제 식별자가 아니다. 평가 수치와 순위는 원본 그대로다. 원본 질문·결과·대응표는 로컬에만 보관하며, 예시 경로는 실제 위치가 아니다.

**목적:** 어떤 문제를 해결하려고 무엇을 바꿨고, 동일 조건의 전후 결과를 보고 왜 채택·보류했는지 남긴다. 이후 실험은 아래에 새 ID로 추가하며, 과거 결과는 덮어쓰지 않는다.

**최근 결과 바로 보기:** [100문항 정확도·지연 비교](2026-09-11-expanded-100.md) · [단계별 실패 진단](2026-09-11-trajectory-rerun.md) · [100문항 전체 결과와 전후 변화](2026-09-11-trajectory-details.md). T07~T09 평가와 실행 도구는 `6aa26ed`에 기록했다.

**현재 운영 구성:** 요청 내 임베딩 공유 + `keep_alive=30m` + 정확한 `Type.Member` 정의 우선 검색 + **벡터:FTS = 4:1 가중 RRF**. bge-m3·BM25·운영 청크는 기존 설정 유지. T06은 운영 검증 후 `898e559`로 커밋했다.

## 비교 기준과 적용 검증

**최신 진단:** T09에서 검색 후보 trace 수집·재실행을 완료했다. vector만 적중한 9개 모두 실제 hybrid의 벡터 후보 상위 5개에 있었으며, 융합 후 6~11위로 밀렸다. 후속 실험은 융합을 우선한다. 전체 에이전트 행동·안전성 평가는 미관측이다.



- **기준 관계:** T01·T02는 같은 성능 개선 커밋에 포함됐다. T01은 예열된 검색 비교, T02는 별도 서버 유휴 비교로 검증했다. T03·T04·T05는 **T01+T02가 적용된 공통 기준선**에서 갈라진 실험이다. T03→T04→T05 순서로 운영에 누적 적용한 것이 아니다.
- **품질 조건:** T03~T05는 같은 코드·문서 혼합 40문항, 3모드, 5회, 캐시 우회로 기준선 포함 **2,400회** 비교. 적중@5는 지정 함수/페이지가 상위 5개에 있는지다. 반복 실행은 독립 정답 표본으로 세지 않는다.
- **범위:** 지연은 로컬 측정이며 HTTP·동시 부하를 제외했다. T02 유휴 비교는 1회로, 최초 로딩이나 30분 초과 유휴까지 없애지는 않는다. 유지 비용은 관측상 모델 VRAM 약 664MB다. 문맥 실험 DB는 새로 구축했으므로 그 지연을 운영 DB와 성능 비교하지 않는다.
- **최종 검증:** 빌드·관련 회귀 테스트 통과. T04 운영 API **120건**의 ID·순서·점수 일치. 운영 10개 워크스페이스 유지, 재색인 없이 반영.
