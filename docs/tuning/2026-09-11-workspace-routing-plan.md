# T12 계획 — 워크스페이스 선택기 비교

**실행 결과:** [T12 구현·학습·신규100개 비교 완료 — 운영 채택 보류](2026-09-11-workspace-routing.md). 아래 본문은 구현 전에 작성한 계획이며, 목표·미실행 표기는 계획 수립 시점을 뜻한다. 시험 전에 범위 순서만 정렬한 대조군을 추가했고 채택 기준은 완화하지 않았다.

**계획 수립 당시:** 구현·학습·검색 실험 미실행. 기준 버전은 `v0.11.2` (`f95eb05`)다. 먼저 임베딩 유사도 선택기를 기준선으로 만들고, 같은 질문 임베딩을 쓰는 작은 ML 분류기가 더 나은지 검증한다. LLM 선택은 별도 비교군으로 다룬다. 채택 여부는 새 시험 질문을 열기 전에 정한 기준으로 결정한다.

## 1. 문제와 확인할 가설

[T11](2026-09-11-release-validation.md)의 원래 범위 hybrid 적중@5는 18/22, 전체 범위는 4/22였다. 원래 범위는 이미 지정된 입력이고 단일 범위에서 다른 융합 정책이 적용되므로, 이 차이는 자동 선택기의 성능이나 순수한 범위 축소 효과가 아니다.

[T10](2026-09-11-vector-prefix.md)에서 모든 워크스페이스에 벡터 순위 보호를 적용한 실험은 입력 순서를 뒤집으면 적중이 23→15로 바뀌었다. 따라서 선택기의 개선과 워크스페이스 간 순위 병합의 개선을 구분한다.

- **가설 A:** 질문과 워크스페이스 설명의 임베딩 유사도로 정답 범위를 보존하면서 검색 대상을 줄일 수 있다.
- **가설 B:** 고정 임베딩 위의 작은 다중 라벨 분류기가 A보다 범위 선택이나 최종 검색 품질을 개선한다.
- **가설 C:** 범위를 올바르게 선택해도 검색 품질이 낮다면 후보 생성·융합·최종 병합에 별도 문제가 남는다.

## 2. 비교할 선택기

| ID | 방법 | 준비·학습 | 역할 |
|---|---|---|---|
| A0 | 현재 전체 검색 | 없음 | 운영 기준선 |
| A1 | 워크스페이스 설명·대표 주제와 질문의 임베딩 유사도 | 설명을 사전 동결; 대표 질문을 쓰면 학습군에서만 추출 | 첫 구현, 학습형 모델의 비교 기준 |
| A2 | 질문 임베딩 → 정규화된 로지스틱 회귀 다중 라벨 분류 | 학습 150문항; 정규화 강도·선택 임계값은 검증 50문항으로 결정 | ML 후보 |
| AO | 라벨로 주어진 적절한 범위 | 정답 범위를 직접 제공 | 진단 참고치; 운영 선택기나 성능 상한으로 단정하지 않음 |
| AL | LLM이 설명 카드를 읽고 범위 선택 | 모델·프롬프트·추론 설정 동결, 추가 학습 없음 | 선택적 비교군 |

A1·A2는 기존 `bge-m3`를 고정한다. 임베더 재학습, BM25·청크·후보 수 변경, 새로운 전역 재정렬 모델은 이번 비교에서 제외한다. A2의 학습은 오프라인에서 수행하고, 운영 추론은 가중치·절편·입력 정규화 정보가 담긴 로컬 JSON을 읽어 Node에서 계산하는 방식을 우선한다. 학습 환경과 내보낸 추론 결과의 수치·선택 일치를 검사한다.

AL을 실행한다면 동일한 질문·카탈로그·허용된 작업 맥락만 제공한다. 정답과 검색 결과는 제공하지 않는다. 기존 호출 LLM의 선택과 별도 LLM 호출을 구분하고, 호출 수·토큰·실제 확인 가능한 비용·지연을 기록한다. 모델 및 호출 환경이 정해지지 않으면 AL은 미실행으로 표시하며 LLM보다 우수하다고 주장하지 않는다.

## 3. 입력과 선택 규칙

워크스페이스 카드는 설명, 별칭, 코드/문서 구분, 대표 주제, 관련 워크스페이스를 가진다. 카드는 시험 질문을 보기 전에 인덱스·메타데이터로 작성한다. 질문·gold를 보고 카드를 보강하지 않는다. 원본 카드·실제 경로·학습 모델은 로컬 비공개 자료다.

| 입력 | 처리 |
|---|---|
| 사용자가 워크스페이스를 지정 | 지정 범위를 그대로 사용; 자동 확대 없음 |
| 사용자가 전체 검색을 지정 | 전체 검색 유지 |
| `auto`를 명시 | 선택기 실행 |
| 기존 클라이언트가 범위를 생략 | 기존 기본값 유지; 자동 선택으로 조용히 변경하지 않음 |

자동 선택은 기본 상위 2개 후보로 시작하며, 검증군에서 동결한 기준으로 1~3개를 선택하거나 전체 검색으로 보류한다. 여러 범위의 근거가 필요한 질문은 하나로 강제하지 않는다. 유사도와 분류기 출력은 같은 척도나 검증된 확률로 취급하지 않는다.

선택 근거가 약함, 유효 후보 없음, 모델·카드 불일치, 임베딩 실패는 전체 검색으로 보류하는 이유로 기록한다. 자동으로 좁힌 범위에 결과가 없거나 검색이 실패하면 전체 범위로 한 번 확대하며 총 작업량과 지연에 포함한다. 결과가 있다는 이유만으로 관련성이 확인됐다고 간주하지 않는다. 콘텐츠 관련성을 판단하는 추가 LLM 호출은 이 단계에 넣지 않는다.

현재 작업 경로 같은 맥락은 클라이언트가 명시적으로 전달한 것만 쓴다. 기본 비교는 질문만으로 수행하며, 맥락 추가 실험은 모든 선택기에 같은 입력을 제공하는 별도 결과로 남긴다. 신규 워크스페이스·모델에 없는 클래스가 생기면 기존 ML 모델만으로 범위를 배제하지 않고, 모델 갱신 전까지 해당 자동 요청을 전체 검색으로 보류한다.

## 4. 데이터 — 개발 200문항, 새 시험 100문항

아래 수는 **확보 목표이며 현재 확보 완료 수가 아니다.** 첫 산출물에서 실제 재사용 가능 수, 중복 제거 수, 보강 필요 수를 보고한다.

| 묶음 | 문항 수 | 사용 |
|---|---:|---|
| 학습 | 150 | A2 학습, A1에 사용할 대표 질문 작성 |
| 검증 | 50 | 임계값·상위 후보 수·정규화 강도 및 최종 후보 선택 |
| 새 봉인 시험 | **100** | 설정 동결 후 최종 확인; 튜닝에 재사용하지 않음 |

기존 100문항·40문항·15문항·실사용 24문항 등은 중복과 근거를 확인한 뒤 **개발군으로만** 재사용할 수 있다. 과거 15문항도 이미 개봉했으므로 새 시험군이 아니다. 검색용 gold를 그대로 분류 학습에 넣지 않고 범위 라벨을 보강하며, 부족한 개발 질문은 새로 확보한다.

봉인 시험의 구성은 단일 범위 60, 여러 범위가 실제로 필요한 질문 20, 범위가 모호해 보류가 적절한 질문 10, 카탈로그 밖 질문 10으로 총 100개다. 단일 범위 60개는 현재 10개 워크스페이스에 6개씩 배분한다. 개발군의 범위·의도 분포도 공개하고, 학습군은 각 워크스페이스에 확정 양성 사례가 최소 10개 있도록 확보한다. 코드·문서를 함께 포함한다.

같은 질문의 바꿔쓰기, 같은 증거 대상, 동등한 증거 묶음, 같은 작업 세션의 밀접한 질문은 같은 분할에 배치한다. 개별 문장만 무작위로 나누지 않는다. 실제 기록과 새로 작성한 질문의 비중·결과를 분리한다. 시험 질문이 실사용에서 충분히 확보되지 않아 새로 작성했다면 실사용 100개라고 부르지 않는다.

라벨은 다음을 구분한다.

- 하나만으로 충분한 **대체 가능 근거 범위**와, 함께 필요한 **필수 근거 범위**. 동일 문서의 복제본은 여러 범위가 모두 필요한 질문으로 세지 않는다.
- 관련 근거 청크와 증거별 의도 충족 범위, 근거 부족·카탈로그 밖·범위 모호성.
- 각 클래스의 확정 양성·확정 음성·미판정. 라벨에 없는 범위를 자동으로 음성 처리하지 않으며 A2 학습에서 미판정 항목은 제외한다.

순위를 보지 않은 독립 라벨 검토로 불일치를 해결한다. 시험 100개는 검색 전 라벨 적합성을 확인하고 동결한다. 그 전에 부적합한 항목은 같은 구간에서 1:1 교체한다. **동결 후에는 100개 모두 실행하고, 불리한 사례를 삭제·교체하지 않는다.** 사후 판정 불가가 발견되면 ID·이유·채점 분모를 별도 공개하고 시험을 불완전으로 표시한다. 적중률의 분모에 카탈로그 밖 질문을 섞지 않는다.

## 5. 공정한 검색 비교

### 5.1 선택 효과만 분리

A0·A1·A2·AO에 같은 후보 생성, topN=5, **범위 수와 무관한 기존 4:1 RRF 정책**을 적용한다. 단일 범위에만 prefix 정책이 켜지는 분기를 실험 하네스에서 명시적으로 통제한다. 반환 후보 수·파일 필터·임베딩·인덱스·소스 버전도 고정한다.

이 결과로 범위 선택 때문에 줄어든 방해 후보와 정답 누락을 측정한다. 별도 진단으로 vector 단독 결과도 확인해 융합 문제와 구분한다. 전역 병합 구현은 이번 단계에서 고치지 않고, 정상/역순/고정 seed 순열에서 차이가 생기는지 기록한다.

### 5.2 실제 운영 정책과 결합

검증군에서 고른 최종 후보를 `v0.11.2`의 실제 분기에 연결한다. 단일 범위는 prefix3, 여러 범위는 4:1 RRF를 쓰는 동작을 A0 및 AO와 비교한다. **5.1의 선택 효과와 5.2의 결합 효과를 따로 보고한다.** 시험 결과를 보고 A1·A2 중 승자를 바꾸지 않는다. 선택되지 않은 모델의 시험 결과는 비교용이다.

순위·품질은 같은 100문항을 방법별 3회 반복해 안정성을 확인한다. 이는 방법·정책 조합당 300회 실행이며 독립 표본은 100개다. 추가 vector 진단·입력 순서 검사·예열·재시도·fallback 호출은 각각 별도 집계한다. 계획서 확정 시 실제 실행 행렬과 예상 호출 수를 기계 판독 가능한 프로토콜로 동결한다.

모든 비교는 캐시 우회, 버전 교대 순서, 같은 원문·인덱스 해시를 사용한다. 반복 호출의 변동과 독립 질문별 차이를 구분한다. 적중 차이는 질문 단위의 쌍별 비교와 불확실성 구간을 보고하고, 바꿔쓰기 묶음이 있으면 묶음 단위로 재표집한다.

## 6. 구현 순서와 연결 위치

| 단계 | 작업 | 완료 산출물 |
|---|---|---|
| P0 | 데이터 재사용 가능 수 확인, 카드·라벨 규격, 분할·게이트 확정 | 비공개 프로토콜·분할 해시, 공개 익명 계획 |
| P1 | A1 오프라인 선택기와 선택 trace, 범위/융합 분리 하네스 | 개발군 기준선, 실패 분류 |
| P2 | A2 학습·내보내기·Node 추론; 검증군에서 후보 결정 | 모델·카드 버전, 추론 동등성 결과, 결정 기록 |
| P3 | 후보·프로토콜 동결 후 새 100개 개봉, 정책별 전후 비교 | 익명 사례별 순위·범위·집계·회귀 보고서 |
| P4 | 통과 후보만 명시적 `auto` API/MCP에 연결, 통합·부하 확인 | 호환성·trace·캐시·동시성 검증 |
| P5 | 소규모 실제 사용에서 선택 결과 관찰, 채택 또는 보류 기록 | 누적 이력·변경 로그, 배포 판단 |

예상 코드 위치는 다음과 같다. 신규 파일명은 구현 시 확정한다.

- `indexer/src/routing.ts` 및 카드/모델 로더: 선택 전략·보류·버전 검증을 공통 구현한다. `config.ts`는 선택기를 기본 비활성으로 둔다.
- `indexer/src/server.ts`: 검색 요청의 명시적 `auto`를 해석한다. 지정 배열 및 `all` 동작을 유지한다.
- `indexer/src/search.ts`·`embed.ts`: 자동 선택과 이어지는 검색이 하나의 지연 생성 임베딩 Promise를 공유하게 한다. 지정 범위의 FTS·정의 우선 검색에서 기존 임베딩 0회 경로를 유지한다. 자동 FTS 요청에서 선택기가 쓴 임베딩은 별도로 계수한다.
- `indexer/src/evidence.ts`: 공통 선택기를 재사용하되 기존 `targets[]` 형태·상태·신선도 검사를 보존한다. 이 API는 현재 범위별 단일 검색 결과를 묶으며 전역 top5 정렬 API가 아니다. 일반 `/api/search`의 적중·병합 결과와 혼합하지 않고 별도 계약 테스트로 확인한다.
- `mcp-server/src/index.ts`·`greplet.ts`, `greplet-mcpb/server/index.js`: 두 MCP 경로에서 같은 명시적 `auto` 의미를 제공한다. 기존 호출 LLM은 설명 카드를 참고해 직접 범위를 지정할 수도 있다.
- `activity.ts`·`activityLog.ts`와 trace 스크립트: 라우팅부터 검색 종료까지 같은 요청 ID로 연결한다. 라우팅 캐시는 질문·제공 맥락·카탈로그·임베더·모델·선택 정책 버전을 포함한다. 검색 캐시는 실제 범위·융합 정책·인덱스 버전을 포함하고 모델 교체 후 오래된 선택 결과가 재사용되지 않도록 검사한다.
- `scripts/`의 신규 평가·내보내기 도구: 기존 trace 도구의 단일 범위·100문항 하드코딩을 이번 다중 범위 프로토콜에 그대로 재사용하지 않는다. 과거 재현 스크립트는 보존한다.

## 7. 측정과 실패 원인

| 단계 | 기록할 관측값 / 실패 |
|---|---|
| 요청 해석 | 명시 범위 무시, auto/전체 구분 오류, 잘못된 후보 slug |
| 선택 | 모델·카드 버전, 후보와 점수, 선택 개수, 보류 이유, 필수 범위 누락 |
| 후보 생성 | 범위는 맞지만 관련 근거 후보 없음, 검색 오류·fallback |
| 범위 내 융합 | 후보에 있던 근거가 범위 내 순위에서 탈락 |
| 전역 병합·반환 | 근거가 전역 top5에서 탈락, 입력 순서 의존, 필터 문제 |
| 확대·종료 | 확대 이유·추가 요청 수·최종 범위, 오류, 총 지연 |

선택 품질은 필수 근거 묶음 충족률, 대체 가능한 범위 중 하나 이상 포함률, 불필요한 범위 수, 보류율을 함께 본다. 전체 검색으로 보류하면 범위 재현율이 높아지는 효과를 숨기지 않도록 **보류 전 선택과 보류 후 결과를 분리**한다.

검색 품질은 답이 있는 질문의 Hit@5·MRR@5 및 여러 근거가 필요한 질문의 근거 묶음 충족률을 본다. 모호·카탈로그 밖 질문은 적절한 보류와 부당한 단일 범위 강제를 따로 채점한다. 최종 답변의 사실성이나 에이전트 전체 행동을 검증했다고 주장하지 않는다.

지연은 선택기 계산만, 임베딩 포함 선택 단계, 최종 검색 전체를 나누어 중앙값·p95를 기록한다. 캐시 우회 1·4·8 동시 요청과 실제 API 캐시 포함 검사를 분리하고, 실제 선택 개수·fallback을 포함한 총 검색 범위 수·메모리를 함께 보고한다.

## 8. 사전 채택 기준

아래는 아직 측정값이 아닌 **제안 게이트**다. P0에서 구현 착수 전에 수치와 분모를 동결하며 시험 결과를 보고 완화하지 않는다.

1. **호환성:** 지정 범위/전체 검색의 ID·순위·점수·응답 계약 회귀 0. 기존 관련 테스트 및 빌드 통과. 자동 요청의 오류·응답 혼선 0; 의도한 장애 주입 fallback은 별도 분류한다.
2. **정답 보존:** 평가 가능한 단일/복수 범위 질문의 보류 후 필수 근거 묶음 충족률 ≥95%. 복수 범위 질문의 필수 범위 누락 0, 모호·카탈로그 밖 질문의 부당한 단일 범위 강제 0.
3. **실제 범위 축소:** 범위를 정할 수 있는 시험 질문의 최소 50%에서 전체 보류·재확대 없이 3개 이하를 검색. 항상 전체로 보내 재현율만 맞추는 후보는 채택하지 않는다.
4. **최종 품질:** 새 시험의 운영 A0 대비 신규 적중이 있고 기존 적중 손실 0, MRR@5 하락 없음. 답이 있는 각 구간의 적중률과 복수 근거 충족률에 회귀 없음. 미판정으로 시험이 불완전하면 채택 판단도 보류한다.
5. **순서 안정성:** 자동 선택 및 채택할 검색 경로의 결과가 카탈로그/워크스페이스 입력 순서에 따라 바뀌지 않음. 기존 A0의 순서 의존은 별도 공개하며, 이를 고쳐야 통과할 경우 병합 수정을 별도 실험으로 기록한다.
6. **지연:** 1·4·8 동시 요청 각각에서 후보의 캐시 우회 end-to-end p95가 같은 실행의 A0 ×1.10 +25ms 이내. 임베딩을 제외한 A1/A2 선택 계산 p95 목표는 10ms 이내로 두고 별도 측정한다. 기존 T11의 지연을 새 실험의 기준선으로 대신 쓰지 않는다.

A2 채택은 위 게이트와 함께 A1보다 추가 적중 또는 동등한 품질에서 명확한 검색 작업량·지연 감소가 검증군과 새 시험에서 유지될 때로 제한한다. 차이가 없으면 A1을 유지한다. 후보가 실패하면 명시 범위/전체 검색을 유지하고 실패 원인과 다음 가설을 남긴다.
