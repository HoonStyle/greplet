# T08 — 단계별 평가 구조 도입

> 후속 실행 완료: [T09 — 같은 100문항의 trajectory 재실행](2026-09-11-trajectory-rerun.md). 아래는 설계 당시의 관측 범위와 재분류 기록이며, 이후 검색 후보·융합·반환 단계 수집을 구현해 재실행했다. 전체 에이전트 단계 수집은 여전히 미구현이다.

**결정:** 최종 적중률과 함께 단계별 관측 증거·실패 위치·미관측 범위를 남긴다. 이번 변경은 평가 구조와 기존 결과 재분류이며, 검색 튜닝이나 새로운 100문항 실험이 아니다.

AgentAudit은 실행 trace를 10개 영역으로 평가하고 행동 분류와 실패 attribution을 함께 다룬다. 2026-09-09 제출된 preprint이며, 단일 judge가 평가 대상에도 포함되는 한계가 명시돼 있다. 모델별 점수나 종합 점수는 가져오지 않고 기록 구조를 참고한다. [원문](https://arxiv.org/abs/2609.09875)

## 기존 100문항에 적용한 결과

| 관측 결과 | 문항 수 | 해석 / 다음 증거 |
|---|---:|---|
| vector·4:1 hybrid 모두 적중 | 55 | 검색 정답 적중. 최종 에이전트 답변의 정확성을 뜻하지 않음 |
| vector만 적중 | 9 | 융합 단계 우선 조사. 동일 hybrid 호출의 후보와 융합 후 순위를 기록해야 위치 확정 가능 |
| hybrid만 적중 | 2 | 융합 이득 사례로 보존 |
| 둘 다 미적중 | 34 | 후보 누락과 순위 탈락을 아직 구분할 수 없음 |

1:1 대비 4:1의 적중 손실은 **E048·E088 두 문항**이다. 이 둘과 vector만 적중한 9문항을 우선 진단한다. 5회 반복은 안정성 확인이며 독립 문항 수는 100이다. 추가 검색 0회, 미실행 예비 15문항은 그대로 유지했다.

상위 5개 결과만으로 임베더·BM25·후보 풀·융합 중 하나를 원인으로 확정하지 않는다. 오류 경고가 없었다는 사실도 보안·안전성 통과를 뜻하지 않는다.

## 다음 실행부터 수집할 trajectory 계약

| 단계 | 필수 증거 | 판정 범위 |
|---|---|---|
| 입력·계획 | trace ID, 익명 문항 ID, 설정·평가군 해시, 관측 가능한 계획 참조 | 계획이 없으면 미관측. 내부 사고 과정은 수집하지 않음 |
| 도구 선택·인자 | 요청 모드, workspace 별칭, topN, 필터, 실제 선택 경로 | 선언한 실행 조건과 실제 호출 일치 |
| 실행 | 단계 시작·종료, 시간, 오류·fallback, 임베딩 호출 수 | 성공·오류·대체 경로 구분 |
| 후보 검색 | 동일 호출의 vector·FTS 후보 수, 목표 후보 존재·순위, pool 제한 | 후보 누락 여부. 누락 원인 자체는 별도 검증 |
| 융합 | 가중치·k, 각 입력 순위, 융합 후 목표 순위 | 후보에 있던 정답의 순위 탈락 |
| 필터·출력 | 필터 전후 존재 여부, topN 절단 전후 순위 | 필터 제외와 최종 순위 탈락 분리 |
| 상태 변화 | 인덱스·소스 해시 전후, 쓰기 발생 여부 | 읽기 평가 중 상태 유지 |
| 최종 응답 | 반환 결과 참조, 목표 적중; 에이전트 응답이 있으면 근거 참조 | 검색 결과와 에이전트 응답 평가는 별도 |

모든 판정에 `status`, `evidenceRefs`, `observedStage`, `causalConfidence`를 둔다. 상태는 pass/fail/not_observed/not_applicable로 구분한다. trace에서 처음 확인된 이상 위치와 실험으로 확인한 원인을 별도 기록한다. 인과 확정에는 후보 풀 고정 등의 통제 실험이 필요하다.

현재 activity 이벤트는 단계 진입·fallback·skip을 제공하지만 후보 순위와 전체 에이전트 행동을 기록하지 않는다. 위 계약의 전체 수집은 **아직 미구현**이다.

## AgentAudit 10개 영역과 적용 경계

tool selection·invocation·correctness·execution integrity는 검색 호출과 실행 증거에 한해 평가한다. instruction integrity·planner·memory·alignment·tool faithfulness·security는 전체 에이전트 trace 또는 해당 시나리오가 있어야 평가한다. 현재 데이터에는 없으므로 미관측이며, 안전한 실패나 Unsafe_Compliance 라벨도 부여하지 않는다.

향후 judge가 필요한 응답 평가에는 judge 모델·버전·rubric·근거·사람의 검토 결과를 함께 기록한다. 단일 judge 점수로 튜닝 채택을 결정하지 않는다. 현재 재분류는 LLM judge 없이 결정 규칙으로 수행했다.

## 재현과 익명화

저장소 루트에서 `node scripts/audit-retrieval-eval.mjs`를 실행하면 [익명 사례별 결과](results/2026-09-11-trajectory-audit.json)를 재생성한다. 입력은 [기존 100문항 집계](results/2026-09-11-expanded-100.json)이며 문항 수·중복·순위 범위·기존 적중 및 회귀 집계 일치를 검사한다.

원문 질문·함수명·경로·후보 텍스트·대응표·원시 인자는 로컬 비공개 자료에 보관한다. 공개 trace에는 익명 ID, 순위, 시간, 설정, 판정과 익명 근거 참조만 포함한다.
