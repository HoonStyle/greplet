# T06 — 벡터 비중을 높인 RRF 융합

2026-09-11 · 기준 구현 `4f72360` · **4:1 가중 RRF 채택·운영 적용** · 구현 커밋 `898e559`.

테스트 대상은 익명으로 표기한다. 원본 질문·함수·프로젝트·소스 경로와 대응표는 저장소 밖 로컬에만 보관한다.

후속 [새 자연어 100문항 확대 검증](2026-09-11-expanded-100.md)에서는 1:1→4:1 적중이 39→57개로 늘었지만 적중 손실 2개도 확인됐다. 아래 내용은 최초 40+8문항 평가 시점의 기록이며, 확대 결과로 한계를 보완한다.

## 문제 → 변경

기존 자연어 21개에서 vector는 13개, hybrid는 9개를 찾았다. vector만 적중한 질문은 4개, 반대로 hybrid만 적중한 질문은 0개였다. 벡터가 찾은 목표를 융합 과정에서 밀어내는지 확인했다.

설치된 LanceDB 0.38.0의 기본 RRF는 양쪽 후보의 순위 기여를 동일하게 합친다. 각 분기의 후보 수는 `max(topN × 10, 50)`이며, 이번 topN=5에서는 분기별 최대 50개다. 두 목록 모두에 있는 후보는 양쪽 점수를 받는다.

```text
기존: score = 1 / (60 + vector_rank) + 1 / (60 + fts_rank)
변경: score = 4 / (60 + vector_rank) + 1 / (60 + fts_rank)
```

여기서 rank는 구현과 같은 **0부터 시작하는 순위**다. 어느 목록에 없으면 해당 항은 0이다. 벡터 점수나 BM25 원점수를 4배 하는 방식이 아니다.

예를 들어 벡터 1위에만 있는 후보의 기존 점수는 약 0.0167이다. 벡터 50위·FTS 1위에 함께 있는 후보는 약 0.0258로 앞선다. 변경 후에는 각각 0.0667과 0.0534가 되어 강한 벡터 후보를 유지할 수 있다. 이는 점수 규칙 설명용 예시이며 모든 질문의 성공을 보장하지 않는다.

후보 풀·임베더·BM25·인덱스·정확한 `Type.Member` 정의 우선 경로는 유지했다. [구현](../../indexer/src/rerank.ts)은 네이티브 RRF의 후보 합집합·스키마를 재사용하고 가중 점수를 계산한다. `_rowid`로 후보를 대응하며, 가중 점수 동점은 해당 호출의 네이티브 순서를 유지한다. 라이브러리 버전을 바꾼 뒤에도 동점 순서가 같다고 보장하지 않는다.

## 후보 선택과 검증 분리

1. 기존 40문항 중 정의 우선 경로를 제외한 32문항의 실제 융합 직전 후보를 추출했다. 네이티브 결과가 저장된 기준선과 일치함을 확인했다.
2. 같은 후보에서 벡터:FTS 비중 1:1 / 2:1 / 4:1을 재계산했다. 전체 hybrid 적중은 28/40 / 30/40 / 31/40이었고, 2:1·4:1 모두 기존 적중 손실이 없었다. 이 단계는 후보 목록 재계산이며 별도 반복 검색으로 세지 않는다.
3. **4:1을 고정한 뒤** 기존 대상과 겹치지 않는 8개 함수·8개 파일에 대해 별도 검토자가 새 자연어 질문을 작성했다. 검색 순위를 보기 전에 원문으로 정답을 확인했다.
4. 새 목표 하나가 병합 멤버 청크로 저장돼 있어 정답의 심볼 표기를 실제 청크에 맞췄다. 최초 존재 검사가 검색 실행 전에 중단됐으며 질문·목표 함수·가중치는 바꾸지 않았다.
5. 기존 40개는 변경 전·후 각각 600회, 신규 8개는 각각 120회 비교했다. 같은 질문, 3모드, 5회, topN=5, 결과 캐시 우회·모드 순서 회전·예열 제외 조건이다. 변경 전 600회는 [직전 재측정](2026-09-11-round2-baseline.md)을 사용했다.

| 기존 코드·문서 40개 | 16→16 | 30→30 | **28→31** | **0.6108→0.6392** |

기존·신규 각각 상위 5개 적중을 잃은 질문은 **0개**다. 그러나 모든 정답 순위가 좋아진 것은 아니다. 익명 사례 D012는 **1→2위**, F006은 **2→3위**로 낮아졌다. 새 8개에서 vector MRR@5는 0.8125로 변경 후 hybrid보다 높다. 가중 hybrid는 더 많은 목표를 상위 5개에 포함했지만, 첫 정답 순위에서 항상 vector보다 우수하지는 않다.

전체 FTS·vector **480회**의 상위 결과·점수·저장된 메타데이터는 변경 전과 동일했다. 정의 우선 검색은 유지했다. 모든 구성에서 5회 상위 결과 순위가 안정적이었고 검색 경고는 0이었다.

## 결정과 운영 확인

**채택:** 기존 질문에서 3개, 신규 질문에서 2개가 추가 적중했고 적중 손실은 없었다. 약 3ms의 지연 증가와 일부 정답 순위 하락을 함께 기록한다. 새 표본은 8개로 작아 일반적인 최적 가중치가 4라고 주장하지 않는다. 이 질문들도 이후부터는 이미 결과를 본 평가 데이터다.

- TypeScript 빌드 및 hybrid 회귀 테스트 통과. 약한 벡터 순위의 어휘 중복 후보가 강한 의미 후보를 밀어내던 합성 사례를 테스트에 추가했다.
- 기존 정확한 심볼·파일 필터·임베딩 공유·실패 폴백 테스트 유지. 후보 런타임의 파일 글롭 테스트도 통과.
- 별도 리뷰로 Arrow 스키마 보존·빈 합집합·동점 순서·행 식별 방식 확인. 최종 소스를 기준으로 **144건**이 반복 측정한 후보 결과와 일치했다.
- 운영 모듈 2개(`search.js`, `rerank.js`)를 백업 절차와 함께 반영했다. 운영 재색인 없음.
