# T10 — 단일 워크스페이스 vector 상위 3개 보호

**결정:** vector 후보 상위 3개를 먼저 배치하고 나머지를 기존 vector:FTS 4:1 RRF(k=60) 순서로 채우는 정책을 **요청 워크스페이스가 정확히 하나일 때만** 적용한다. 여러 워크스페이스를 함께 검색할 때는 기존 4:1 정책을 유지한다. 무조건 적용한 다중 워크스페이스 실험은 입력 순서에 민감해 채택하지 않았다.

이 문서는 기준 커밋 `1722a3c`에서 수행한 검색 전용 실험과 구현 커밋 `ce20623`을 기록한다. 최종 범위 구현의 로컬 전체 반환 검증, 운영 배포·health 검사와 API 결과 대조를 완료했다.

## 주요 결과

| 평가군 | 문항 | 기존 4:1 적중@5 | 보호 정책 적중@5 | 신규 / 손실 | MRR@5 |
|---|---:|---:|---:|---:|---:|
| 개발 | 100 | 57 | **63** | 6 / 0 | 0.3262 → **0.4777** |
| 최초 평가 보류군 | 15 | 8 | **9** | 1 / 0 | 0.3022 → **0.4156** |
| 기존 혼합 회귀군 | 40 | 31 | **32** | 1 / 0 | **0.6392 → 0.6379** |

혼합 회귀군은 적중 한 건을 늘리고 손실은 없었지만 MRR이 소폭 하락했다. 이를 순위 품질 개선으로 표현하지 않는다.

vector 단독 결과는 개발군 64건(MRR@5 0.4807), 최초 평가 보류군 10건(MRR@5 0.4322), 혼합 회귀군 30건(MRR@5 0.5183)이었다. 보호 hybrid는 개발군과 최초 평가 보류군에서 vector 단독보다 각각 1건 낮았고, 혼합 회귀군에서는 2건 높았다.

개발군 신규 적중은 **E011·E013·E015·E022·E084·E102**다. 기존 vector 단독 적중 9개 중 이 6개를 복구했고 **E018·E019·E028**은 남았다. 기존 적중을 잃지는 않았지만 E005는 2→3위, E016은 2→3위, E027은 3→5위, E042는 1→3위로 내려갔다.

최초 평가 보류군은 후보 선택과 동결 뒤 처음 열었다. 사전 통과 기준은 적중 증가 최소 1건, 기존 적중 손실 최대 0건이었으며 실제 결과는 증가 1건·손실 0건이었다. 신규 적중은 **E078(미적중→3위)**, 적중 내 순위 하락은 **E061(4→5위)**이며 손실은 없다. 이 평가는 독립 표본 15개에 한정되므로 일반화 근거가 제한적이다. 이 15개는 T10에서 사용을 마쳤으므로 이후 변경의 fresh holdout으로 재사용하지 않는다.

혼합 40문항은 원본 배열 순서대로 **M001~M040**을 부여했다. 신규 적중은 **M016(미적중→3위)**이다. 적중 손실은 없고 M006 1→2위, M012 2→3위, M029 1→2위, M034 4→5위로 하락했다.

## 후보 선택과 동결

후보 정책은 모두 이전에 고정한 동일 vector·FTS 목록(각각 최대 50개)을 오프라인에서 재정렬했다. 사전 규칙은 개발군에서 적중을 최소 3개 늘리고, 기존 적중 손실이 없으며, MRR이 감소하지 않아야 한다는 것이었다. 적중@5, MRR@5, 등록 순서로 동률을 판정하고 문항별 정책 선택은 금지했다.

| 후보 | 적중@5 | MRR@5 | 신규 | 손실 | 판정 |
|---|---:|---:|---:|---:|---|
| 기존 4:1, k=60 | 57 | 0.3262 | 0 | 0 | 기준 |
| 4:1, k=20 | 62 | 0.4123 | 7 | 2 | 제외 |
| 4:1, k=10 | 62 | 0.4387 | 7 | 2 | 제외 |
| 8:1, k=60 | 61 | 0.3863 | 6 | 2 | 제외 |
| vector 상위 3개 보호 | **63** | **0.4777** | 6 | **0** | 선택 |

다른 k와 가중치 후보는 모두 E027·E041 두 기존 적중을 잃어 사전 규칙을 통과하지 못했다. 선택 정책을 먼저 고정한 뒤 최초 평가 보류군 15개를 열었고, 개봉 뒤 재조정하지 않았다.

선택 정책은 vector 상위 3개를 원래 vector 순서로 둔 다음, 중복을 제거한 기존 4:1 RRF 순서로 나머지를 채운다. 최종 순서를 검색 응답 정렬에서 보존하고 정확한 정의의 점수 1보다 아래에 두기 위해 0.5를 최댓값으로 하는 float32 ordinal 점수를 사용한다. 이는 신뢰 확률이 아니며, 단일 워크스페이스 내부 순서 표시에만 사용한다.

## 실제 재실행과 회귀

개발 100개, 최초 평가 보류군 15개, 혼합 40개를 두 버전·세 모드·5회로 재실행해 총 **4,650회** 실제 검색을 수행했다. 모든 문항의 반복 순위가 같았고, FTS와 vector 결과 **1,550쌍**은 두 버전에서 동일했다. 개발군의 기존 실행 1,500건과 오프라인에서 예측한 보호 정책 hybrid 500건도 실제 재실행과 일치했다. 반복 실행은 독립 문항으로 세지 않는다.

| 평가군 | hybrid 중앙값 ms (전→후, Δ) | hybrid p95 ms (전→후, Δ) |
|---|---:|---:|
| 개발 | 61.6838 → 63.0177, **+1.3339** | 70.1651 → 71.1300, **+0.9649** |
| 최초 평가 보류군 | 58.6901 → 59.9902, **+1.3001** | 66.2437 → 67.5147, **+1.2710** |
| 기존 혼합 회귀군 | 58.2511 → 59.3694, **+1.1183** | 70.1493 → 72.4002, **+2.2509** |

latency는 동일 문항·모드의 paired 실행 요약이며 채택 기준에는 사용하지 않았다. 빌드와 `test:fusion-protection`, `test:hybrid`, `test:file-glob`가 통과했고 이 라우팅·순서 검증은 CI에도 추가했다.

이 변경은 앞선 단계별 관측에서 vector 후보에 있었지만 융합 뒤 최종 5개 밖으로 밀린 사례를 대상으로 한다. 복구된 6개는 융합 단계 손실이었고, 보호 범위 아래에 있던 3개는 남았다. 후보 누락의 원인, 임베딩 품질, 에이전트 계획·최종 답변·안전성은 이 실험에서 별도로 평가하지 않았다.

## 다중 워크스페이스 적용 거부

10개 워크스페이스를 한꺼번에 검색한 100문항을 정상·역순으로 각각 실행했다. 기존 정책은 적중 18→18이었지만 무조건 보호 정책은 **23→15**로 바뀌었다. 상위 5개 순서가 입력 순서에 따라 달라진 문항도 기존 20개에서 보호 정책 100개로 늘었다. 두 버전과 두 순서의 실제 검색은 총 400회이며 경고와 오류는 없었다.

원인은 워크스페이스 내부 ordinal 점수를 전역 점수처럼 섞을 수 없다는 점이다. 따라서 무조건 전역 적용은 거부하고, 최종 소스는 요청 워크스페이스가 하나일 때만 보호 정책을 사용하며 둘 이상이면 기존 4:1 RRF를 유지한다.

## 최종 적용 검증

최종 범위 소스로 **774회**를 실행했다.

- 단일 워크스페이스 155쌍의 전체 반환이 동결한 보호 후보와 동일했다.
- 다중 워크스페이스 정상·역순 200쌍의 전체 반환과 메타데이터가 기존 4:1 정책과 동일했다.
- topN 1·3·10·20과 파일 필터 32쌍의 전체 반환이 동결 후보와 동일했다.
- 경고는 0건이었고 인덱스·manifest는 검사 중 변하지 않았다.
- 컴파일 파일 2개를 백업한 뒤 14:23 KST에 운영 배포했고, health 검사와 10개 워크스페이스 유지 확인을 통과했다.

운영 API에서도 단일 155문항×3모드 465회의 상위 5개 ID·점수·메타데이터가 기준과 같았고, 다중 100문항×2순서 200회의 전체 ID·점수·순서가 기존 정책과 같았다. 총 **665/665회**가 일치했으며 경고는 0건, 서비스는 10개 워크스페이스에서 정상 상태였다.

최초 4,650회 paired 측정 중에는 대상 원문과 인덱스가 일치했다. 마지막 범위 검증 전에 원문 파일 2개의 외부 변경을 감지했지만 인덱스는 바뀌지 않았다. 따라서 774회 결과는 **동결 인덱스에서의 정책·라우팅 동등성**을 입증하며, 변경된 최신 원문에 대한 검색 품질을 새로 검증한 결과가 아니다.

## 제약과 재현 범위

- pool=50, topN=5, 캐시 우회, 버전 교차 순서, 5회 반복 조건이다.
- 원시 질문·대상·경로·후보 내용과 익명 대응표는 저장소 밖에 보관한다.
- 수치와 익명 ID는 [공개 집계 JSON](results/2026-09-11-vector-prefix.json)에 기록했다.
- 후보 생성이나 청크·임베딩을 바꾸지 않았으므로 결과를 후보 검색 개선으로 해석하지 않는다.
- 최초 평가 보류군 15개는 이제 사용 완료 상태다. 다음 변경은 새로운 holdout을 마련해야 한다.
- AgentAudit에서 참고한 단계 구분 중 검색 후보·융합·최종 절단만 관측했다. 전체 AgentAudit 점수나 에이전트 안전성 결과가 아니다.
