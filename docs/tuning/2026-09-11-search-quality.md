# 검색 품질 개선안 비교 — 2026-09-11

> 공개용 익명 표기: 테스트 대상 함수·클래스·프로젝트·질문 ID와 로컬 경로를 대체했다. `Type001.Method001`은 함수 F001을 뜻하며 실제 식별자가 아니다. 평가 수치와 순위는 원본 그대로다. 원본 질문·결과·대응표는 로컬에만 보관하며, 예시 경로는 실제 위치가 아니다.

## 결론

앞선 검증은 [유휴·실패 유형 보고서](2026-09-11-idle-validation.md)에 기록했다. 이후 고정 질문 40개에 대해 기준선·문맥 보강·정의 우선·두 변경 조합을 각각 5회 측정했다. 총 2,400회 검색이다.

**운영에는 hybrid의 정확한 `Type.Member` 정의 우선 검색만 반영했다.** 해당 질문의 목표 구현 적중@5가 6/8에서 8/8로 개선되고, 8개 모두 정답이 1위였다. 나머지 검색은 ID·순서·점수가 동일했다. 임베더 모델, BM25, RRF 가중치, 청크, 운영 인덱스는 변경하지 않았다.

클래스 설명을 메서드 청크에 전달하는 안은 전체 적중 수를 조금 높였지만, 기존에 찾던 구현을 놓치는 회귀가 있어 채택하지 않았다. 실험 코드와 별도 인덱스를 보존했다. **자연어 검색 문제가 해결된 것은 아니다.** 원래 함수 F001의 자연어 질문은 채택안의 hybrid에서도 상위 5개에 목표 메서드가 없다.

## 평가 설계

- 기존 회귀 질문 12개: 신규 프로젝트 A 코드, 레거시 프로젝트 B 코드, 설계 문서/PDF 혼합.
- 앞선 실패 진단 질문 17개: 4개 함수의 자연어 표현 변형 12개, 정확한 식별자 4개, 원래 실패 질문 1개.
- 별도 평가 질문 12개: 앞서 집중 분석한 함수와 다른 함수들에 대한 자연어 8개와 식별자 4개. 별도 검토자가 소스에서 정답을 확인하고 검색 순위를 보기 전에 작성했다.
- 회귀군과 진단군에 원래 실패 질문 1개가 겹쳐, 중복 제거 후 40개다. 아래 군별 수치를 단순 합산하면 안 된다.
- 각 구성에서 동일한 질문·정답·워크스페이스·상위 5개 기준을 유지하고, `fts` / `vector` / `hybrid`를 5회 반복했다. 모드 순서를 회전하고 결과 캐시를 우회했다.
- 목표 파일과 지정 메서드 또는 PDF 페이지가 상위 5개에 있는지를 측정했다. 파일만 맞거나 클래스 설명·호출부만 반환한 경우 목표 적중으로 세지 않았다. 모든 정답 청크가 평가 인덱스에 있음을 확인했다.

이는 알려진 목표 구현을 찾는 **target Hit@5 / MRR@5** 평가다. 모든 반환 청크의 관련성을 평가한 precision이나 서비스 전체 정확도가 아니다. 표현 변형과 반복 실행을 독립 업무 표본으로 세지 않는다. 별도 평가군도 12개로 작으며, 이번 결과를 본 뒤에는 향후 튜닝의 완전히 새로운 평가군으로 사용할 수 없다.

## 동일 조건 비교 결과

| 구성 | FTS 목표 적중@5 | vector 목표 적중@5 | hybrid 목표 적중@5 | hybrid MRR@5 |
|---|---:|---:|---:|---:|
| 기준선 | 16/40 | 30/40 | 26/40 | 0.5042 |
| 클래스 문맥 보강만 | 20/40 | 31/40 | 27/40 | 0.5404 |
| **정의 우선만 — 채택** | **16/40** | **30/40** | **28/40** | **0.6108** |
| 문맥 보강 + 정의 우선 | 20/40 | 31/40 | 29/40 | 0.6563 |

모든 구성·모드에서 40개 질문의 상위 5개 ID와 순서는 5회 동안 안정적이었다. 검색 경고와 결과 캐시 적중은 0이었다.

| hybrid 평가군 | 기준선 | 문맥만 | 정의 우선만 | 조합 |
|---|---:|---:|---:|---:|
| 기존 회귀 12개 | 11/12 | 11/12 | 11/12 | 11/12 |
| 진단 17개 | 5/17 | 7/17 | 7/17 | 8/17 |

조합의 총 적중 수가 가장 높아도 회귀가 사라진 것은 아니다. 문맥 보강 시 `Q005`는 vector와 hybrid 모두 5위에서 상위 5개 밖으로 밀렸다. hybrid의 `Q006`가 새로 적중해 별도 자연어군 합계는 6/8로 같지만, 개별 질문에서는 교환이 발생했다. 진단군의 `Q002-B`, `Q003-B`도 hybrid 적중을 잃었다. 별도 자연어군 vector 합계는 7/8에서 6/8로 낮아졌다.

따라서 전체 합계의 작은 증가만으로 문맥 보강을 기본 청크 정책으로 배포하지 않았다. 클래스 설명이 항상 무익하다는 뜻이 아니라, 일괄 전달 정책을 이번 결과로 채택하기 어렵다는 뜻이다.

## 채택한 정의 우선 검색

hybrid에서 입력 전체가 대소문자를 구분하는 한정 식별자일 때 `symbol` 메타데이터로 정의를 찾는다. 예: `Type001.Method001`. 일반 문장에 식별자가 포함된 경우는 기존 hybrid 검색을 그대로 사용한다.

- 오버로드, 분할 메서드 청크(`#n`), 작은 멤버 병합 청크를 처리한다.
- 파일 글롭 조건을 정의 조회에도 적용한다.
- 해당 워크스페이스에서 정의가 없거나 선택적 조회가 실패하면 기존 검색으로 진행한다.
- 정의 조회는 임베딩이 필요 없어 임베딩 없는 인덱스에서도 가능하다. 그 외 검색은 기존 FTS 강등 규칙을 따른다.
- `fts`, `vector` 명시 모드는 기존 동작을 유지한다. 내부 `symbolFirst: false` 옵션으로 비교를 위한 우회가 가능하며 캐시 키도 구분한다.
- 이는 정의 메타데이터 조회이며 참조/호출 관계 분석은 아니다. 정의 조회 결과는 고정 점수 1을 사용한다. 같은 이름의 여러 오버로드 중 의미적으로 가장 관련 있는 것을 재정렬하는 기능은 추가하지 않았다.

진단 식별자군은 2/4에서 4/4로, 별도 식별자군은 4/4를 유지하며 모두 1위가 됐다. `Type001.Method001`, `Type003.Method003`가 새로 상위 5개에 들어왔다. 별도군에는 이미 찾던 결과를 5위/3위에서 1위로 올린 사례가 있다. 별도군의 적중 수 자체가 늘었다고 주장하지 않는다.

기준선과 채택안의 600회씩을 대조한 결과:

- 변경 대상 식별자 hybrid 40회(8문항 × 5회)는 모두 정답 1위, 임베딩 호출 0회.
- 나머지 560회는 상위 5개 결과의 ID·순서·점수·저장된 본문/메타데이터가 동일.
- 식별자 hybrid 40회의 중앙값: **56.97 → 10.55ms**, 임베딩 호출 합계: **40 → 0회**.
- 전체 hybrid 200회의 중앙값은 59.35 → 59.08ms로 거의 같다. 자연어 검색의 속도 개선으로 해석하지 않는다.

속도 수치는 같은 운영 DB에 대한 로컬 함수 호출이며 HTTP 전송 시간은 제외한다. 시간대를 나눠 실행했으므로 정밀한 동시 부하 성능 보장은 아니다. 문맥 실험 DB는 새로 복제·구축했으므로 그 구성의 낮은 지연을 문맥 보강의 성능 효과로 비교하지 않는다.

## 문맥 실험 보존

실험은 직접 포함 타입의 XML summary를 정규화하고 최대 800자로 잘라 자식 멤버 청크에 전달했다. 중첩 타입은 자신의 설명만 사용하고, 멤버 병합/분할 이후 헤더를 붙여 식별자와 원문 줄 범위를 유지했다.

운영 10개 테이블을 별도 DB로 복제했다. 신규 코드 3,094행 중 C# 2,948청크를 재추출했고, 2,295청크의 설명 헤더와 그 임베딩을 갱신했다. 원본 파일 해시, 청크 ID, 종류, 줄 범위가 같음을 확인했다. 다른 워크스페이스 데이터는 복사해 유지했다. 실험 DB를 운영 DB로 교체하지 않았다.

실험 구현에는 C# 청크 버전을 파일별로 기록해 변경 없는 파일도 1회 재추출하는 마이그레이션과 실패 재시도 검증도 포함했다. 이 변경은 채택하지 않은 문맥 보강에만 필요하므로 최종 소스에서는 함께 제거했다. 후보 코드는 보존 패치（로컬 보관: `<LOCAL>/artifacts/quality/context-candidate/tracked.patch`）, Extractor 후보（로컬 보관: `<LOCAL>/artifacts/quality/context-candidate/Extractor/CSharpChunker.cs`）, 청크 테스트（로컬 보관: `<LOCAL>/artifacts/quality/context-candidate/scripts/test-csharp-type-summary.mjs`）, 마이그레이션 테스트（로컬 보관: `<LOCAL>/artifacts/quality/context-candidate/indexer/tests/chunkerVersion.mjs`）에 남겼다.

## 남은 판단

BM25는 이미 LanceDB FTS에서 사용한다. 이번 실패는 BM25 미구현이 원인이 아니므로 다시 작성하지 않았다. 임베더 재학습도 이번 실험 범위에 없으며, 현재 결과만으로 필요성을 입증하지 못했다.

자연어에서는 vector가 hybrid보다 목표를 더 잘 찾는 질문이 남아 있다. 다음 실험은 별도의 신규 자연어 평가군을 준비해 질의별 융합 정책이나 reranking을 비교하는 편이 근거에 맞다. 이번 결과만 보고 모든 자연어 요청을 vector로 전환하거나, 기존 평가군에 맞춰 문맥 길이를 반복 조정하지 않았다.
