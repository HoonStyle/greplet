# 워크스페이스 선택기 연구 비교 — T12 후속 검토

**판단:** 검색 범위를 선택하는 방식에는 성능·효율 개선 사례가 있다. LLM과 학습형 분류기의 우열은 데이터와 도메인에 따라 달랐다. Greplet은 범위 구분 라벨과 검색 결과 결합 방식을 보강할 근거가 있으며, LLM 선택기도 비교 기준선에 포함할 가치가 있다.

검토일: **2026-09-11**. [T12 시험](2026-09-11-workspace-routing.md) 후 작성한 연구 검토다. 추가 검색 실험은 **0회**이며 운영 구성·버전은 그대로다. 아래 논문 수치는 Greplet에서 재현한 성능이 아니다.

## 한눈에 보는 연구 결과

세 연구의 지표·데이터·기준선이 다르므로 수치를 서로 순위 매기거나 Greplet의 적중@5로 환산하지 않는다. 이 검토는 세 원문의 비교이며, 연구 전체에 대한 체계적 문헌 조사나 최신 모델의 우열 판정은 아니다.

## 1. ReSLLM: 학습 유무와 모델에 따라 결과가 달랐다

**FedWeb-14의 149개 검색엔진, 키워드형 질의, nDCG@20** 조건이다. nDCG는 관련 검색 대상을 앞에 배치하는 순위 품질이며, 0.7088을 정답률 70.88%로 읽지 않는다.

| 방법 | nDCG@20 | 비교 시 주의점 |
|---|---:|---|
| 임베딩 기준선 BGE-large-en-v1.5 | 0.2418 | 로그의 검색 결과 발췌문으로 검색 대상을 표현 |
| 기존 비지도 기준선 | 0.4220 | 임베딩 기준선보다 강한 비교 대상도 존재 |
| ReSLLM Solar, 추가 학습 없음 | 0.4227 | 검색 대상의 이름·URL 사용 |
| ReSLLM Flan-XL, 추가 학습 없음 | 0.1845 | 같은 무학습 조건에서도 모델에 따라 BGE보다 낮음 |
| SLAT + ReSLLM Flan-XL | 0.7088 | 검색 로그·발췌문을 LLM이 평가한 합성 라벨로 학습 |
| 기존 지도학습 기준선 | 0.7120 | 사람 라벨·외부 API·여러 방법 결합 등 추가 정보 사용 |

Solar와 학습한 Flan의 차이를 같은 모델의 전후 개선으로 계산하지 않는다. 이 연구는 검색 대상 순위를 평가했으며 RAG 최종 답변의 개선을 직접 검증하지 않았다. **근거:** [ReSLLM §4.2–4.5, 표 4·5, §6](https://arxiv.org/html/2401.17645v1).

## 2. MKP-QA: 제품 문서에서는 학습한 라우터와 점수 결합이 유효했다

BERT 라우터가 질의별 도메인 확률을 예측하고, 불확실성을 고려해 여러 도메인을 검색한다. 최종 문서 순위에는 **도메인 관련 확률 × 문서 관련 점수**를 사용한다. 학습형 단일 도메인 필터는 비교군 중 강했고, GPT-4의 무학습 도메인 선택은 검색 정확도에서 부진했다.

데이터에는 전문가 작성·검토 질문과 합성 질문이 포함된다. 같은 페이지나 관련 페이지의 문서를 이용해 헷갈리기 쉬운 음성 예제도 구성했다. 검색기 자체도 관련·비관련 문서 쌍으로 학습했다. 따라서 결과는 **데이터·라우팅·검색·결합을 포함한 시스템 비교**다. 그래프의 높이를 임의로 숫자로 옮기지 않았으며, 논문의 배포 목표인 정확도 90%·p95 10초는 달성 결과로 기록하지 않는다. **근거:** [MKP-QA §3–6](https://arxiv.org/html/2501.14998v1).

## 3. RAGRoute: 작은 분류기로 검색 작업량을 줄인 사례

하나의 경량 3층 신경망이 질의 임베딩, 소스 중심 벡터, 둘 사이 거리, 소스 크기·밀도를 받아 해당 소스를 검색할지 예측한다. 학습 라벨은 **전체 소스 검색 결과의 통합 top-k에 해당 소스의 문서가 들어가는지**다. 이는 사람이 판정한 정답 범위와 다른 대리 목표다.

MMLU에서는 검색 요청 **13,890→3,126회**, 통신량 **73.3→17.42MB**였고, 답변 정확도는 **43.59%→43.29%**였다. 의료 QA인 MIRAGE의 top-32 조건에서는 평균 정확도 **72.22%→72.24%**였다. 관측 차이는 작지만 통계적 비열등성을 입증한 결과는 아니다. 소스 수가 적고, MMLU는 10개 인공 분할을 사용했으므로 운영 10개 워크스페이스와 같은 조건으로 취급하지 않는다. **근거:** [RAGRoute §3.2, §4.1–4.5, 표 2](https://2025.euromlsys.eu/pdf/euromlsys25-14.pdf).

T12의 AO 34/80은 실제 운영 융합 정책 기준이다. 모든 범위에 같은 4:1 RRF를 고정하면 AO는 **33/80**이다. 범위 선택 효과와 융합 정책 차이를 분리한다. **근거:** [T12 결과·실패 단계·라벨 한계](2026-09-11-workspace-routing.md).

## 다음 검증의 우선순위 — 제안, 미실행

1. **설계 전에 비교 조건 정리:** 기존 방법, 필요한 라벨·소스 특징, 우리 조건과 차이, 평가 지표를 먼저 고른다. [T12 사전 계획](2026-09-11-workspace-routing-plan.md)에도 일반 구현 문서 참고는 있었지만, 이번 논문 비교는 시험 후 보강한 내용이다.
2. **데이터 적합성 확인:** 비슷한 범위끼리의 확정 음성, 복수 범위 정답, 보류 질문을 구분한다. 미판정을 음성으로 바꾸지 않는다. 검색 top-k에서 만든 대리 라벨과 정답 근거 라벨도 구분한다.
3. **작은 개발 실험:** 전체 검색·설명 유사도·학습형·LLM 선택기를 비교한다. 후보 풀을 고정한 범위 선택만의 효과, 최종 점수 결합만의 효과, 두 변경의 조합을 나눠 본다. 불확실할 때 범위를 넓히는 정책도 검증한다.
4. **설정 동결 후 새 시험:** 필수 범위 보존, 적중·MRR·복수 근거 완성, 총 검색 범위 수, 임베딩·선택·검색 지연을 함께 측정한다. T12의 100개는 미사용 시험군으로 다시 세지 않고, 반복 횟수를 독립 질문 수로 세지 않는다.

이 문서는 후속 실험의 근거다. T12의 수치·채택 보류 결정은 해당 시점의 이력으로 보존하며, 새 실험의 변경·전후 결과·채택 여부는 별도 기록으로 추가한다. 공개 문서에는 내부 함수명·프로젝트명·질문 원문·로컬 경로를 포함하지 않는다.
