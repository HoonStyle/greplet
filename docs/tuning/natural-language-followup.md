## 기존 데이터에서 확인한 우선순위

저장된 동일 조건 검색 결과의 첫 회차를 재분류했다. 새 검색을 수행하거나 운영 설정을 바꾸지 않았다. 진단군은 자연어 표현 12개와 원래 실패 질문 1개, 별도군은 자연어 8개다. 두 집합 모두 이미 평가에 사용했으므로 새로운 검증군이 아니다.

| 목표 적중@5 분류 | 진단군 13개 | 기존 별도군 8개 | 합계 |
|---|---:|---:|---:|
| vector·hybrid 모두 적중 | 3 | 6 | 9 |
| **vector만 적중** | **3** | **1** | **4** |
| hybrid만 적중 | 0 | 0 | 0 |
| **둘 다 미적중** | **7** | **1** | **8** |

**먼저 볼 대상은 융합에서 밀린 4개다.** vector 상위 5개에 목표가 있는데 hybrid 상위 5개에서는 빠진다. 현재 저장된 후보 목록으로 두 모드의 차이를 확인할 수 있다. 다만 이것만으로 모든 자연어 검색을 vector로 바꾸지는 않는다.

**둘 다 놓친 8개는 후보 순위를 더 확인해야 한다.** 상위 5개 밖이라는 사실만으로 목표가 전체 후보에서 누락됐거나 임베더 성능이 원인이라고 단정할 수 없다. 목표 청크 존재는 앞선 평가에서 확인했으며, 그다음은 더 넓은 후보 범위의 순위·본문 문맥 확인이다.

1. 기존 21개를 개발·진단용으로 유지하고, 실패 유형별 후보 순위를 분석한다.
2. 실사용에서 새로 나온 사례를 아래 형식으로 로컬에 기록한다. 튜닝 전에 정답을 확인한다.
3. 새 평가군을 고정한 뒤 한 가지 융합/재정렬 변경씩 비교한다. 총 적중뿐 아니라 기존 적중 손실, 지연, 반복 안정성을 함께 기록한다.
4. 실제 변경을 실험한 뒤 튜닝 히스토리에 새 ID를 부여한다. 이번 재분류를 새 튜닝 성과로 세지 않는다.

## 새 실사용 실패 기록 양식

아래 빈 양식을 복사해 **저장소 밖 로컬 기록**에 작성한다. 공개 문서로 옮길 때는 사례·함수·워크스페이스 ID와 결과 수치만 사용한다. 실제 질문과 소스 식별자 대응표는 공개하지 않는다.

| 필드 | 작성 내용 |
|---|---|
| 사례 ID / 발생일 | 새 익명 ID / 날짜 |
| 구현 / 인덱스 기준 | 커밋 / 인덱스 갱신 시점 |
| 워크스페이스 | 익명 ID; 실제 경로는 로컬 대응표에만 기록 |
| 실제 질문 | 로컬에만 원문 보관 |
| 기대 결과 | 익명 함수/문서 ID; 원문으로 확인했는지 표시 |
| 검색 조건 | mode, topN, fileGlob, 캐시 사용 여부 |
| 실제 결과 | 목표 순위 또는 미적중; 원본 결과는 로컬 보관 |
| 비교 결과 | 동일 질문의 FTS / vector / hybrid 목표 순위 |
| 실패 분류 | vector만 적중 / 둘 다 미적중 / 정답 라벨 불확실 / 기타 |
| 평가군 용도 | 개발·진단용 또는 튜닝 전에 고정할 새 검증용 |

목표 순위를 아직 측정하지 않았다면 **미측정**으로 남긴다. 미측정과 상위 K개 미적중을 같은 값으로 기록하지 않는다. 표현만 다른 동일 함수 질문은 독립적인 업무 표본으로 합산하지 않는다.
